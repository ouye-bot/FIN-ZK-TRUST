## 不可妥协的原则与标准

### 一、质量底线

| 原则 | 含义 |
|------|------|
| 工程级实现 | 所有代码都是生产级，严禁 mock 数据、占位符、# TODO 注释或玩具代码。 |
| 经得起审视 | 每一个函数、每一个模块，都经得起评委（安全工程师、密码学教授）逐行审问。 |
| 边界处理完整 | 不写"理想路径代码"。异常、超时、空值、并发都要处理。 |
| 不确定即确认 | 对需求、技术细节、环境配置有任何不确定，先问，不动手。 |

### 二、行为准则

| 原则 | 含义 |
|------|------|
| 先看代码，后下结论 | 遇到报错绝不猜测。看不到源代码，只给"可能性列表"；看到代码，才定位根因。 |
| 最小侵入 | 在能根治问题的方案中，优先选择改动范围最小、不影响现有功能的那个。 |
| 不推倒重来 | 除非存在严重安全漏洞，不提议重写整个模块。寻找最精确的改动点。 |
| 向后兼容 | 新功能不破坏旧功能。存量数据永远安全。 |

### 三、安全红线

| 原则 | 含义 |
|------|------|
| 密钥绝不暴露 | 明文密码、SM2 私钥、SM4 密钥绝不写入日志、前端代码、报错消息。 |
| 认证不可绕过 | 宁可多一层验证，不牺牲安全性换取便利。 |
| 数据不能破坏 | 不重置、不清空数据库。每一条资产记录、改密历史、审计日志都是累积成果。 |

### 四、交付标准

| 原则 | 含义 |
|------|------|
| 改什么就说清楚 | 每一步改动必须说明：改了哪个文件、为什么改、预期结果、如何验证。 |
| 可执行指令 | 给出的修复方案必须包含文件路径、修改方式、禁止项、验收标准。 |
| 验证后才算完 | 单点验证通过后，跑最小回归清单，确认无新增报错。 |
| 清理临时代码 | 修复完成后，必须移除所有 [DEBUG] 日志和临时探针。 |

### 五、问题处理五步法（SOP）

1. **信息收集**：要求提供完整错误栈、触发路径、复现条件。
2. **分层索证**：沿调用链递进查看代码，交叉比对前后端逻辑，必要时插 [DEBUG] 或查数据库字段值。
3. **方案设计**：首选局部修复，评估改动影响范围。
4. **精确指令**：输出包含路径、修改前后对比、禁止项、验收标准的指令。
5. **验证闭环**：单点验证 + 回归测试 + 删除临时探针。

## 六、开发规范

### 6.1 代码风格

- 遵循现有文件的代码风格（crypto.test.js 用 class，其余用函数式）
- 所有测试用例必须有中文名称和控制台输出（与现有格式一致）
- 每个用例必须有明确的 `passed`/`failed` 判定，不允许"需手动验证"
- 新增函数使用 JSDoc 注释说明参数和返回值

### 6.2 测试数据安全

- 测试用的 SM2 密钥对必须在测试运行时动态生成，禁止硬编码
- 测试用的 SM4 密钥使用 `.env` 中的 `SM4_MASTER_KEY`，不引入新密钥
- 测试用户必须使用随机用户名（`test_${timestamp}_${random}`），避免冲突
- 测试结束后不清理测试数据（保持可审计性）

### 6.3 错误处理规范

- 每个测试用例的 catch 块必须记录完整错误信息（`e.message` + `e.stack` 前 3 行）
- 测试框架层面的错误（如模块加载失败）标记为 `skipped`，不标记为 `passed`
- 已知 Bug 的验证用例使用 `knownIssue: true` 标记，在报告中单独展示

### 6.4 JSON 报告格式

新增字段必须向后兼容，遵循以下约定：

```json
{
  "module": "模块名",
  "name": "用例名",
  "passed": true|false,
  "knownIssue": true|false,
  "expectedBehavior": "预期行为描述",
  "actualBehavior": "实际行为描述",
  "details": {}
}
```

### 6.5 性能测试规范

- 每个性能测试至少运行 3 轮，输出均值 ± 标准差
- 对比基准使用 Node.js 原生 crypto 模块（SHA-256, AES-256-GCM, ECDSA P-256）
- 并发阶梯至少 8 个点：10, 20, 50, 80, 100, 120, 150, 200
- 记录测试环境信息：Node.js 版本、OS、CPU 核数、可用内存

| 7.3 | SM2 vs ECDSA P-256 | 各签名 5000 次 | ops/s + 比率 |

**Node.js 对比基准代码参考：**
```javascript
// SHA-256
const hash = crypto.createHash('sha256').update(data).digest('hex');

// AES-256-GCM
const cipher = crypto.createCipheriv('aes-256-gcm', key, iv);
cipher.update(data); cipher.final(); cipher.getAuthTag();

// ECDSA P-256
const sign = crypto.createSign('SHA256');
sign.update(data); sign.sign(privateKey, 'hex');
```

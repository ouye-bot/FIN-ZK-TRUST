# FinZkTrust - 隐私金融信贷系统

基于国密算法与零知识证明的隐私金融信贷系统，实现"数据可用不可见"的隐私信用评估，同时构建企业级纵深安全防御体系。

## 核心特性

- **端侧零知识证明**：浏览器本地利用 Web Worker 和 WASM 生成 Groth16 证明，证明用户信用达标而不泄露真实分数；后端只进行验证
- **全链路国密合规**：SM2 用于身份认证和交易签名，SM3 用于哈希和完整性校验，SM4 用于敏感数据加密存储
- **金融业务闭环**：借款、还款（先息后本、提前还款）、出资、赎回、资金池管理，利率按信用评分差异化定价
- **五层纵深安全**：接入层 → 路由层 → 业务层 → 数据层 → 传输层，全方位安全防护
- **区块链存证**：Hardhat 私链上部署 AuditStorage、ZKPVerifier、TransactionHashStorage 三个合约，记录操作哈希和公钥锚定
- **密钥生命周期**：SM4 主密钥作为 KEK 保护多个 DEK，支持版本化轮换、Shamir 秘密共享灾备恢复
- **MFA 多因素认证**：基于 RFC 6238 标准的 TOTP 动态口令，种子经 SM4 加密存储
- **高性能架构**：PM2 集群 + ZKP 子进程池 + 数据库连接池调优

## 快速开始

### 前置要求

- Node.js >= 18.x
- MySQL >= 8.0
- Hardhat (用于区块链本地节点)

### 安装步骤

1. **克隆仓库**

```bash
git clone <repository-url>
cd fin-zk-trust-master
```

1. **安装依赖**

```bash
# 后端依赖
cd backend
npm install

# 前端依赖
cd ../frontend
npm install

# 电路编译依赖
cd ../circuits
npm install

# 合约编译依赖
cd ../contracts
npm install
```

1. **配置环境变量**

在 `backend/.env` 中配置以下变量：

| 变量名                   | 说明            | 格式要求                |
| --------------------- | ------------- | ------------------- |
| `SM4_MASTER_KEY`      | SM4 主密钥（128位） | 32 位十六进制字符串，禁止使用弱密钥 |
| `JWT_SECRET`          | JWT 签名密钥      | 至少 32 个字符，禁止使用默认弱值  |
| `SESSION_SECRET`      | Session 密钥    | 至少 32 个字符           |
| `DB_HOST`             | 数据库主机         | IP 地址或域名            |
| `DB_PORT`             | 数据库端口         | 默认 3306             |
| `DB_USER`             | 数据库用户名        | -                   |
| `DB_PASSWORD`         | 数据库密码         | -                   |
| `DB_NAME`             | 数据库名称         | 默认 finzktrust       |
| `HARDHAT_PRIVATE_KEY` | 区块链签名私钥       | 64 位十六进制，前缀 0x      |
| `PORT`                | 服务端口          | 默认 3003             |

生成密钥命令：

```bash
# 生成 SM4 主密钥（32位十六进制）
node -e "console.log(require('crypto').randomBytes(16).toString('hex'))"

# 生成 JWT 密钥（32位随机字符串）
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

1. **启动数据库**

```bash
# 创建数据库表（首次运行）
node backend/scripts/create-tables.js
```

1. **启动 Hardhat 节点**

```bash
cd contracts
npx hardhat node
```

1. **部署合约**

```bash
cd contracts
npx hardhat run scripts/deploy.js --network localhost
```

1. **启动后端服务**

```bash
cd backend
npm start
# 或使用 PM2 集群模式（生产环境推荐）
pm2 start ecosystem.config.js
```

1. **启动前端服务**

```bash
cd frontend
npm start
```

## 核心业务流程

### 借款流程

1. 用户登录获取 JWT 令牌（支持 MFA）
2. 生成信用证明（端侧 ZKP）
3. 提交借款请求（含 SM2 签名）
4. **大额借款（≥5,000 元）触发挑战-应答式 SM2 二次签名确认**
5. 后端验证：
   - JWT 有效性检查
   - SM2 签名验证
   - ZKP 验证（信用分达标证明）
   - 风险评估
6. 资金池扣款，生成交易记录
7. 异步上链存证

### 还款流程

1. 用户提交还款请求（含信用证明和 SM2 签名）
2. 验证信用证明有效性
3. **部分还款遵循先息后本原则：优先抵扣利息，剩余归还本金**
4. **提前还款按实际占用天数计息，取约定利息与实际利息的较小值**
5. 更新用户余额和信用分
6. 逾期还款按逾期天数计算罚息（日利率翻倍）
7. 异步上链存证

### 出资/赎回流程

1. 用户发起出资/赎回请求（含信用证明和 SM2 签名）
2. **信用证明校验**
3. **资金池可用余额检查（赎回时精确校验可赎回金额）**
4. **大额赎回（≥10,000 元）触发挑战-应答式 SM2 二次签名确认**
5. 更新用户余额和资金池状态
6. 交易哈希上链存证

### ZKP 验证流程

```
前端生成证明 (Web Worker + WASM)
        │
        ▼
   发送 proof + publicSignals
        │
        ▼
后端验证 (snarkjs.groth16.verify)
        │
        ▼
   验证结果上链存证
```

## 安全机制

### 五层纵深安全架构

1. **接入层**：Helmet 安全响应头 + 速率限制（登录 5 次/分钟，通用 200 次/分钟）+ Joi 参数校验
2. **路由层**：JWT 黑名单（内存 + 数据库双重存储）+ 防重放（时间戳 + Nonce）+ 异常行为检测（四类规则）+ 权限校验
3. **业务层**：大额操作 SM2 二次签名（借款 ≥¥5,000，赎回 ≥¥10,000）
4. **数据层**：SM4 密文存储（余额、信用分等敏感字段）+ SM3 哈希链审计日志 + DAO 透明加解密
5. **传输层**：TLS 终止代理架构，后端不持有 TLS 私钥，可扩展国密 TLCP

### MFA 多因素认证

- 基于 RFC 6238 标准的 TOTP 动态口令
- 种子经 SM4 加密存储
- 支持备份验证码（SM3 哈希存储）

### Shamir 秘密共享（SSS）灾备恢复

- SM4 主密钥支持 k/n 门限分片
- 离线保管分片
- 拉格朗日插值恢复

### 密钥版本化轮换

- 支持密钥轮换脚本 (`rotate-key.js`)
- 旧数据兼容解密
- 轮换审计日志记录

### 区块链服务降级

- Hardhat 节点不可用时，上链操作自动跳过
- 核心业务不受影响
- 日志记录降级状态
